# 3. Обоснование планируемых изменений «Будущее 2.0»

## 1. Обоснование этапов с точки зрения бизнеса

### Q1: Архитектурное проектирование и пилот облака
- Бизнес-ценность: без согласованной архитектуры невозможно масштабирование.
- Влияние: ускоряет принятие решений за счёт прозрачных границ доменов.
- Снижение затрат: пилот облака показывает реальную экономию на инфраструктуре.

### Q1: Выделение Clinical и Medical Records Domain
- Бизнес-ценность: изоляция медицинских карт снижает регуляторные риски.
- Качество услуг: врачи работают в современном интерфейсе.
- Масштабирование: клиники развиваются независимо от финтеха и ИИ.

### Q1: Запуск Integration Domain (Kafka)
- Бизнес-ценность: замена устаревшего ESB на событийную шину.
- Надёжность: сбой одного домена не останавливает другие.
- Скорость: новые сервисы подключаются через API Gateway за дни.

### Q2: Выделение Fintech Domain
- Бизнес-ценность: банковская лицензия требует изоляции.
- Выручка: финтех-продукты запускаются быстрее.
- Compliance: аудит проходит без влияния на клиники.

### Q2: Запуск AI Services Domain
- Бизнес-ценность: ИИ-сервисы становятся конкурентным преимуществом.
- Качество медицины: поддержка принятия врачебных решений.
- Масштабирование: ML-модели развиваются независимо.

### Q2: Миграция DWH в Lakehouse
- Бизнес-ценность: отчёты строятся за минуты, а не часы.
- Скорость решений: руководство получает данные оперативно.
- Снижение затрат: облачное хранилище дешевле поддержки SQL Server 2008.

### Q3: Портал самообслуживания
- Бизнес-ценность: бизнес-пользователи сами строят отчёты.
- Скорость: time-to-market аналитики сокращается с недель до часов.
- Качество: единые метрики и каталог данных.

### Q3: Partner Integration Domain
- Бизнес-ценность: новые партнёры (фарма, электроника) подключаются быстро.
- Выручка: совместные продукты с партнёрами.
- Масштабирование: экосистема растёт без изменения DWH.

### Q3: Corporate Domain
- Бизнес-ценность: консолидированная отчётность по всем направлениям.
- Скорость: стратегические решения на основе актуальных данных.

### Q4: Полный перевод аналитики в Lakehouse
- Бизнес-ценность: отказ от устаревшей СУБД.
- Снижение затрат: нет лицензий SQL Server 2008.
- Масштабирование: данные растут до петабайт без деградации.

### Q4: Развитие портала самообслуживания
- Бизнес-ценность: все домены работают с данными в единой среде.
- Скорость: self-service analytics для всех сотрудников.

### Q4: Отказоустойчивость и аварийное восстановление
- Бизнес-ценность: соблюдение SLA и регуляторных требований.
- Надёжность: геораспределение защищает от сбоев.
- Качество: бесперебойная работа клиник и банка.

### Q4: Отказ от легаси
- Бизнес-ценность: снижение затрат на поддержку.
- Скорость: команды работают с современными технологиями.
- Масштабирование: нет ограничений устаревших систем.

## 2. Итоговые эффекты для бизнеса

| Эффект                          | Способ достижения                                                         |
|---------------------------------|---------------------------------------------------------------------------|
| Скорость принятия решений       | Lakehouse + портал самообслуживания + семантический слой                  |
| Качество медицинских услуг      | Современный интерфейс врача, ИИ-поддержка, изоляция медданных             |
| Качество финансовых услуг       | Core Banking в облаке, compliance, отказоустойчивость                     |
| Снижение затрат                 | Отказ от легаси, облачная инфраструктура, автоматизация                   |
| Масштабирование                 | Доменная архитектура, Data Mesh, облако                                   |
| Time-to-market                  | Независимые домены, API Gateway, партнёрская интеграция                   |
| Регуляторные требования         | Изоляция медданных и финданных, IAM, аудит                                |
| Надёжность                      | Kafka, геораспределение, резервные копии, наблюдаемость                   |

## 3. Вывод

Переход к доменной архитектуре на базе облака и Data Mesh позволяет «Будущему 2.0»:
- развивать клиники, финтех, ИИ и партнёрские направления независимо,
- ускорить вывод продуктов на рынок;
- обеспечить соответствие требованиям регуляторов;
- снизить затраты на поддержку легаси;
- масштабироваться под рост данных и новые направления бизнеса,

что стратегически необходимо для сохранения конкурентоспособности и реализации экосистемной модели компании.
